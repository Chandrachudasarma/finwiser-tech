Design Rationale

One idea, not four features

The slide says advice is a RELAY of specialists, not a feature list. Everything serves that.

The mess IS the problem

Nodes 2 & 3 show real difficulty — 30+ accounts, stacks of statements — that must collapse into one answer. The collapse proves how hard each single leg genuinely is.

Dependency shown, not claimed

Node 4 — the actual advice — can only fire if 1-2-3 feed it. Showing the three hand toward a locked node 4 makes the dependency literal, not rhetorical.

To-do list, not dashboard

Node 4's output is a 3-item checklist, not charts — the advice should be steps, not data. Here it appears only as a ghost, so you feel exactly what never arrives.

Ends unresolved on purpose

The slide is pure problem; the next slide reveals the solution. The dead baton — broken handoffs, node 4 never lighting — makes the viewer crave the team that completes the relay.

Colour system

Pink = a step firing / proven. Green = a hard leg resolved. Grey = dormant/locked. Red baton in the gap = the handoff that breaks between separate apps.
